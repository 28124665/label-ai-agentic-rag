# 面试口述稿：Claim 级可追溯幻觉检测

## 开场（30 秒）

我们在 Agentic RAG 里做的不是「整段答案像不像真的」这种粗粒度打分，而是 **Claim 级、可追溯、可 fail-closed 的幻觉检测**。

核心思路三句话：

1. **先锁定证据**：工具产出先融合成不可变 Evidence Snapshot  
2. **再拆主张核对**：答案拆成 Claim，逐条对证据做 support / contradict / insufficient  
3. **最后策略拍板**：Policy Engine 统一决定放行、过滤、重写或拒答，渲染层只输出过审内容  

目标是：关键事实说错就拦；验证服务坏了不装通过；重写不是盲目再抽一次，而是带着失败原因重写。

---

## 完整链路（1.5～2 分钟）

可以按流水线讲：

**第一步：Evidence Fusion**  
RAG / DB / Web 等工具跑完后，统一进融合节点，建成不可变快照。重试时按「来源类型 + tool_run_id」精确替换本轮工具证据，保留未重试工具的证据，避免把反证误删。还会做来源配额，防止单一来源挤掉别的证据。

**第二步：质量检查**  
材料不够可以回工具重试，但只要再产出，必须再过融合，保证后面验证始终对着同一份权威快照。

**第三步：Citation-aware Prompt + LLM 生成**  
证据全局编号 `[1][2][3]`，强制模式下要求模型输出结构化 Answer AST，每个 Claim 带引用。同时下发 `snapshot_id`，验证和引用共用同一证据视图。

**第四步：Hallucination 入口（门禁）**  
先看强制级别：`DISABLED` 兼容老路径，`SHADOW` 影子验证，`ENFORCED` 严格 fail-closed。  
空答案、无证据、AST 解析失败、验证服务异常，在 ENFORCED 下不会悄悄放行，而是 regenerate 或 reject。

**第五步：CitationBinder（Claim 验证闭环）**  
这是核心：

- 解析引用，**原始声明、非法编号、越权引用、合法证据分开存**，不覆盖模型原话  
- 每个 Claim–Evidence pair **独立裁决**，一个 pair 出错不影响其他  
- **反证扫描**：模型没引用、但证据里有冲突的也要找出来  
- 支持联合蕴含：单条不够、多条拼起来能支撑也算 support  
- 有验证预算（Claim 数、pair 数、LLM/NLI 调用、超时），预算耗尽就停，避免雪崩  

**第六步：VerdictMatrix**  
把多层验证结果压成最终状态：verifier_error / contradicted / insufficient / supported。  
规则按优先级短路；验证器异常优先于矛盾，避免把「服务挂了」误判成「事实冲突」。

**第七步：PolicyEngine（唯一决策者）**  
Gateway 只返回 claim verdicts，**不直接给 action**。策略引擎统一拍板：

- 关键 Claim 矛盾 → 一票否决拒答  
- 事实模式下关键 Claim 不足 → 拒答  
- 验证器大面积异常 → 拒答  
- 忠实度高 → pass；中等 → filter；偏低可重试 → regenerate；用尽 → exhausted  

忠实度是**加权**的：关键金额/日期/身份类 Claim 权重大，防止琐碎正确句淹没关键错误。  
Regenerate 会带 forbidden claims、allowed evidence、差异化指令，避免简单重复抽样。

**第八步：Answer Renderer**  
只有 pass/filter 进渲染；同步验证后状态，**只输出 supported Claim**。reject/exhausted 跳过渲染，直接拒答或保守答案，避免幻觉内容出站。

## 面试官最爱追问：你解决了什么坑？

可以主动提 4 个设计点：

1. **不可变快照**：Prompt、Verifier、References 共用同一 `snapshot_id`，防止「验证时证据和生成时证据不是一套」  
2. **fail-closed**：严格模式下「审不了 ≠ 通过」  
3. **引用可审计**：非法 `[999]`、越权引用都留痕，方便排障和合规  
4. **决策与验证分离**：Binder/Matrix 负责「判真假」，Policy 负责「怎么处置」，避免各处各自 return action 导致行为不一致

## 收尾（20 秒）

所以这套系统本质是把幻觉检测从「相似度感觉」升级成「主张级证据法庭」：

> 证据锁定 → 主张拆解 → 逐对验证 + 反证扫描 → 规则裁决 → 策略决策 → 过滤渲染  

在 Agentic RAG 这种多工具、可重试场景里，它能保证：**关键事实有据、失败可解释、异常可拦截、重写可收敛。**

---

## 可选加分句（被问到取舍时）

- **为什么不全用 LLM 判幻觉？** 成本高、不稳定、难审计；我们用规则/NLI/LLM 分层，再加预算和 fail-closed。  
- **为什么不直接删非法引用？** 要可追溯：模型到底声称了什么，和系统最终采信了什么，必须分开。  
- **和传统 RAG faithfulness 分数差在哪？** 传统是文档级/段落级；我们是 Claim 级，并且和引用编号、快照、策略动作闭环。
