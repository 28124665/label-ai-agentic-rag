# 计划执行器与并行调度逻辑设计文档

## 1. 背景与目标

### 1.1 问题背景

当前意图路由的第3层 Planner 已经能够生成带并行标记的 DAG 执行计划（`ExecutionPlan`），但存在两个断层：

1. **计划未被执行**：Planner 生成的计划仅存储在 `state["route_decision"].metadata["plan"]` 中，后续节点并未读取和使用
2. **不支持多工具并行**：现有 `db_tool_node` / `rag_tool_node` 是单实例调用，且 `AgentState` 中 `db_result`、`rag_docs` 都是单值字段，无法承载多个并行查询结果

### 1.2 典型场景

> 用户提问："一分厂一月份的人力成本和物料成本是多少？有没有已统计好的报告？"

期望执行计划：

```
step1: database (db_id=hr_system)     ──┐
step2: database (db_id=supply_chain)  ──┤── 并行
step3: rag      (kb_ids=[report_kb])  ──┘
                                        ↓
                                   结果聚合 → prompt_assembly
```

- step1 查人力系统数据库获取人力成本
- step2 查供应链系统数据库获取物料成本
- step3 查知识库是否有已统计好的报告
- 三者无依赖关系，可并行执行
- 结果汇总后进入 prompt_assembly

### 1.3 设计目标

1. **支持并行执行多个同类/异类工具**（如多个 DB + RAG 并行）
2. **基于 DAG 依赖关系调度**（无依赖并行，有依赖串行）
3. **与现有流程有机融合**（简单任务仍走原流程，复杂任务走计划执行器）
4. **结果统一聚合**（多源结果合并到 merged_context）
5. **向后兼容**（不破坏现有 hybrid 串行逻辑）

## 3. 总体架构设计

### 3.1 核心思路：新增"计划执行器"节点

在 intent_router 和 quality_check 之间，新增一个 **`plan_executor`** 节点，作为复杂任务的统一执行入口：

```
intent_router
    ├── route_target = "complex" → plan_executor → quality_check → ...
    ├── route_target = "rag"     → rag_tool → quality_check → ...
    ├── route_target = "database"→ db_tool  → quality_check → ...
    └── route_target = "chitchat"→ prompt_assembly
```

**设计原则**：只有 Planner 判断为 complex 的任务才走计划执行器，简单任务仍走原流程，保证最小侵入。

### 3.2 整体流程图

```
                    ┌─────────────────────────────────────┐
                    │        intent_router_node           │
                    │  (三层递进：过滤→规则→LLM→Planner)   │
                    └────────────────┬────────────────────┘
                                     │
                           route_decision()
                                     │
                    ┌────────────────┼────────────────┐
                    │                │                │
                    ▼                ▼                ▼
              "complex"        simple targets    "chitchat"
                    │           (rag/db/web)         │
                    ▼                │               ▼
          ┌─────────────────┐       │        prompt_assembly
          │ plan_executor   │       │
          │ (并行调度DAG)   │       ▼
          └────────┬────────┘  rag_tool / db_tool / web_tool
                   │                 │
                   ▼                 ▼
             quality_check ◄─────────┘
                   │
                   ▼
             prompt_assembly → llm_generate → ...
```

### 3.3 与现有系统的融合点

| 融合点 | 方案 |
|--------|------|
| **路由分发** | `route_decision()` 新增 `"complex"` 分支，指向 `plan_executor` |
| **State 扩展** | 新增 `tool_results` 字段存储多工具结果，保留原字段向后兼容 |
| **质量检查** | `quality_check_node` 新增对 `tool_results` 的聚合评分逻辑 |
| **Prompt 组装** | `prompt_assembly_node` 新增从 `tool_results` 读取多源结果的逻辑 |
| **工具复用** | 计划执行器内部调用现有 `RAGTool.invoke()` / `DatabaseTool.invoke()`，不重写工具 |

```python
# agent/langgraph/nodes/plan_executor.py

async def plan_executor_node(state: AgentState) -> dict[str, Any]:
    """计划执行器节点。

    读取 state["route_decision"].metadata["plan"]，
    按 DAG 依赖关系并行执行所有步骤，
    将结果聚合到 state["tool_results"]。

    Args:
        state: 当前 AgentState

    Returns:
        dict: 更新的状态字段
    """
    start_time = time.time()

    # 1. 获取执行计划
    route_decision = state.get("route_decision")
    if not route_decision or "plan" not in route_decision.metadata:
        logger.error("[plan_executor] 未找到执行计划")
        return _fallback_to_simple_route(state)

    plan = ExecutionPlan(**route_decision.metadata["plan"])

    # 2. DAG 调度执行
    scheduler = DAGScheduler()
    tool_results = await scheduler.execute(plan, state)

    # 3. 聚合结果到兼容字段
    aggregated = ResultAggregator.aggregate(tool_results)

    elapsed_ms = int((time.time() - start_time) * 1000)
    logger.info(
        f"[plan_executor] 计划执行完成: {len(tool_results)} 个步骤, "
        f"{elapsed_ms}ms"
    )

    return {
        "tool_results": tool_results,
        "execution_plan": plan,
        "plan_execution_status": "completed",
        # 同步写入兼容字段（确保 quality_check 和 prompt_assembly 兼容）
        "rag_docs": aggregated.get("rag_docs", []),
        "rag_quality_score": aggregated.get("rag_quality_score", 0.0),
        "rag_has_relevant": aggregated.get("rag_has_relevant", False),
        "rag_relevant_count": aggregated.get("rag_relevant_count", 0),
        "rag_top_score": aggregated.get("rag_top_score", 0.0),
        "db_result": aggregated.get("db_result", {}),
        "db_quality_score": aggregated.get("db_quality_score", 0.0),
        "web_docs": aggregated.get("web_docs", []),
        "node_timings": {"plan_executor": elapsed_ms},
    }
```

### 4.3 DAG 调度器设计

#### 4.3.1 核心算法

```python
# agent/langgraph/executor/dag_scheduler.py

class DAGScheduler:
    """DAG 调度器。

    基于拓扑排序执行 DAG，同一层级（无依赖关系）的步骤并行执行。
    """

    async def execute(
        self, plan: ExecutionPlan, state: AgentState
    ) -> list[ToolResult]:
        """执行 DAG 计划。

        执行策略：
        1. 将步骤按依赖关系分层（拓扑排序）
        2. 同层步骤用 asyncio.gather 并行执行
        3. 不同层串行执行
        4. 每层完成后，将结果传递给依赖该层的下一层

        Args:
            plan: 执行计划
            state: 当前状态

        Returns:
            list[ToolResult]: 所有步骤的执行结果
        """
        results: dict[str, ToolResult] = {}

        # 1. 拓扑分层
        layers = self._topological_layers(plan.steps)

        # 2. 逐层执行
        for layer_idx, layer in enumerate(layers):
            logger.info(
                f"[DAGScheduler] 执行第 {layer_idx + 1} 层: "
                f"{[s.step_id for s in layer]}"
            )

            # 同层并行执行
            layer_results = await asyncio.gather(
                *[self._execute_step(step, state, results) for step in layer],
                return_exceptions=True,
            )

            # 收集结果
            for step, result in zip(layer, layer_results):
                if isinstance(result, Exception):
                    logger.error(
                        f"[DAGScheduler] 步骤 {step.step_id} 执行失败: {result}"
                    )
                    results[step.step_id] = ToolResult(
                        step_id=step.step_id,
                        tool=step.tool,
                        success=False,
                        error=str(result),
                    )
                else:
                    results[step.step_id] = result

        return list(results.values())

    def _topological_layers(self, steps: list[PlanStep]) -> list[list[PlanStep]]:
        """拓扑排序分层。

        将 DAG 分为多个层级，同一层级的步骤无依赖关系，可并行执行。

        算法（Kahn's algorithm 变体）：
        1. 第0层：无依赖的步骤
        2. 第N层：所有依赖都在前 N-1 层的步骤

        示例：
            step1 (无依赖)     → 第0层
            step2 (无依赖)     → 第0层
            step3 (依赖step1, step2) → 第1层
            step4 (依赖step3)  → 第2层

        Args:
            steps: 步骤列表

        Returns:
            list[list[PlanStep]]: 分层后的步骤列表

        Raises:
            ValueError: 检测到循环依赖
        """
        step_map = {s.step_id: s for s in steps}
        completed: set[str] = set()
        layers: list[list[PlanStep]] = []

        remaining = list(steps)
        while remaining:
            # 找出当前可执行的步骤（所有依赖已完成）
            current_layer = [
                s for s in remaining
                if all(dep in completed for dep in s.depends_on)
            ]

            if not current_layer:
                # 循环依赖检测
                raise ValueError(
                    f"检测到循环依赖，未完成的步骤: "
                    f"{[s.step_id for s in remaining]}"
                )

            layers.append(current_layer)
            for s in current_layer:
                completed.add(s.step_id)
                remaining.remove(s)

        return layers

    async def _execute_step(
        self,
        step: PlanStep,
        state: AgentState,
        previous_results: dict[str, ToolResult],
    ) -> ToolResult:
        """执行单个步骤。

        将步骤分发到对应的工具执行器，并收集结果。
        """
        dispatcher = get_tool_dispatcher()
        return await dispatcher.dispatch(step, state, previous_results)
```

```
  step2: database(db_id=supply_chain), depends_on=[]
```

### 4.4 工具分发器设计

```python
# agent/langgraph/executor/tool_dispatcher.py

class ToolDispatcher:
    """工具分发器。

    根据 PlanStep.tool 调用对应的工具实例，
    复用现有 RAGTool / DatabaseTool / WebTool 的 invoke() 方法。
    """

    async def dispatch(
        self,
        step: PlanStep,
        state: AgentState,
        previous_results: dict[str, ToolResult],
    ) -> ToolResult:
        """分发步骤到对应工具。

        Args:
            step: 执行步骤
            state: 全局状态
            previous_results: 前置步骤结果（可用于步骤间数据传递）

        Returns:
            ToolResult: 工具执行结果
        """
        start_time = time.time()

        try:
            if step.tool == "rag":
                result = await self._execute_rag(step, state)
            elif step.tool == "database":
                result = await self._execute_database(step, state)
            elif step.tool == "web":
                result = await self._execute_web(step, state)
            else:
                raise ValueError(f"未知工具类型: {step.tool}")

            result["step_id"] = step.step_id
            result["tool"] = step.tool
            result["success"] = True
            result["latency_ms"] = int((time.time() - start_time) * 1000)
            return ToolResult(**result)

        except Exception as e:
            logger.error(f"[ToolDispatcher] 步骤 {step.step_id} 执行失败: {e}")
            return ToolResult(
                step_id=step.step_id,
                tool=step.tool,
                success=False,
                error=str(e),
                latency_ms=int((time.time() - start_time) * 1000),
            )

    async def _execute_rag(self, step: PlanStep, state: AgentState) -> dict:
        """执行 RAG 检索。

        复用 get_rag_tool()，但使用 step.args 中的参数覆盖 state 默认值。
        """
        rag_tool = get_rag_tool()

        # 步骤参数优先，state 兜底
        input_data = {
            "query": step.args.query or state.get("user_question", ""),
            "query_simplified": step.args.query_simplified
            or state.get("query_simplified", "")
            or state.get("user_question", ""),
            "query_lang": state.get("query_lang", "zh_CN"),
            "kb_ids": step.args.kb_ids or state.get("kb_ids", []),
            "tenant_id": state.get("tenant_id", ""),
        }

        result = await rag_tool.invoke(input_data)

        return {
            "rag_docs": result.get("docs", []),
            "rag_quality_score": result.get("quality_score", 0.0),
            "rag_has_relevant": result.get("has_relevant", False),
            "rag_relevant_count": result.get("relevant_count", 0),
            "rag_top_score": result.get("top_score", 0.0),
            "kb_ids": step.args.kb_ids,
        }

    async def _execute_database(self, step: PlanStep, state: AgentState) -> dict:
        """执行数据库查询。

        关键：使用 step.args.db_id 指定具体数据库实例，
        支持同一计划中查询多个不同数据库。
        """
        db_tool = get_database_tool()

        agent_config = state.get("agent_config", {}) or {}
        db_config = agent_config.get("database_config", {}) or {}

        input_data = {
            "query": step.args.query or state.get("user_question", ""),
            "query_simplified": step.args.query_simplified
            or state.get("user_question", ""),
            "query_lang": state.get("query_lang", "zh_CN"),
            # ★ 关键：使用步骤指定的 db_id，而非 state 中的全局 db_id
            "db_id": step.args.db_id or state.get("db_id", ""),
            "tenant_id": state.get("tenant_id", ""),
            "llm_id": state.get("llm_id", ""),
            "mcp_server_name": step.args.mcp_server_name
            or state.get("mcp_server_name", "database_mcp_server"),
            "enable_self_healing": db_config.get("enable_self_healing", True),
            "enable_template": db_config.get("enable_template", True),
        }

        result = await db_tool.invoke(input_data)

        return {
            "db_result": result,
            "db_quality_score": result.get("quality_score", 0.0),
            "db_id": step.args.db_id,
        }

    async def _execute_web(self, step: PlanStep, state: AgentState) -> dict:
        """执行 Web 搜索。"""
        web_tool = get_web_tool()

        input_data = {
            "query": step.args.query or state.get("user_question", ""),
            "query_lang": state.get("query_lang", "zh_CN"),
        }

        result = await web_tool.invoke(input_data)

        return {
            "web_docs": result.get("docs", []),
        }
```

### 4.5 结果聚合器设计

```python
# agent/langgraph/executor/result_aggregator.py

class ResultAggregator:
    """结果聚合器。

    将多个工具的执行结果聚合为统一格式，
    兼容现有 quality_check 和 prompt_assembly 的字段读取方式。
    """

    @staticmethod
    def aggregate(tool_results: list[ToolResult]) -> dict[str, Any]:
        """聚合多工具结果。

        聚合策略：
        - RAG 结果：合并所有 docs，按 score 降序排列
        - DB 结果：合并所有 rows，标注来源 db_id
        - Web 结果：合并所有 docs
        - 质量评分：取所有成功步骤的最高分

        Args:
            tool_results: 工具执行结果列表

        Returns:
            dict: 聚合后的结果，字段与原 state 兼容
        """
        all_rag_docs = []
        all_db_rows = []
        all_web_docs = []
        max_rag_score = 0.0
        max_db_score = 0.0

        for result in tool_results:
            if not result.get("success", False):
                continue

            # 聚合 RAG 结果
            if result.get("rag_docs"):
                all_rag_docs.extend(result["rag_docs"])
                max_rag_score = max(max_rag_score, result.get("rag_quality_score", 0.0))

            # 聚合 DB 结果（支持多数据库）
            if result.get("db_result") and result["db_result"].get("rows"):
                db_result = result["db_result"]
                db_id = result.get("db_id", "unknown")
                # 为每行标注来源数据库
                for row in db_result["rows"]:
                    row["_source_db"] = db_id
                all_db_rows.extend(db_result["rows"])
                max_db_score = max(max_db_score, result.get("db_quality_score", 0.0))

            # 聚合 Web 结果
            if result.get("web_docs"):
                all_web_docs.extend(result["web_docs"])

        # RAG docs 按 score 降序
        all_rag_docs.sort(key=lambda x: x.get("score", 0.0), reverse=True)

        # 构建聚合后的 db_result
        aggregated_db_result = {
            "rows": all_db_rows,
            "row_count": len(all_db_rows),
            "source": "multi_db" if len(all_db_rows) > 0 else "",
            "is_aggregated": True,
        }

        return {
            "rag_docs": all_rag_docs,
            "rag_quality_score": max_rag_score,
            "rag_has_relevant": len(all_rag_docs) > 0,
            "rag_relevant_count": len(all_rag_docs),
            "rag_top_score": all_rag_docs[0].get("score", 0.0) if all_rag_docs else 0.0,
            "db_result": aggregated_db_result,
            "db_quality_score": max_db_score,
            "web_docs": all_web_docs,
        }
```

## 5. 完整执行流程示例

### 5.1 场景：一分厂人力成本和物料成本

**用户输入**："一分厂一月份的人力成本和物料成本是多少？有没有已统计好的报告？"

**Step 1: intent_router_node**
```
第0层前置过滤：未命中
第1层规则路由：confidence=0.5（关键词模糊），进入第2层
第2层 LLM 路由：complexity="complex"，进入第3层
第3层 Planner 生成计划：
  plan_id: "plan_001"
  steps:
    - step1: database, db_id="hr_system", can_parallel=True
    - step2: database, db_id="supply_chain", can_parallel=True
    - step3: rag, kb_ids=["report_kb"], can_parallel=True
```

**Step 2: route_decision()**
```
route_decision.source == "planner"
route_decision.complexity == "complex"
→ 返回 "plan_executor"
```

**Step 3: plan_executor_node**

```
DAGScheduler._topological_layers():
  Layer 0: [step1, step2, step3]  ← 全部无依赖

并行执行 Layer 0 (asyncio.gather):
  step1: DatabaseTool.invoke(db_id="hr_system")
         → rows=[{hr_cost: 500000}], score=0.9
  step2: DatabaseTool.invoke(db_id="supply_chain")
         → rows=[{material_cost: 1200000}], score=0.85
  step3: RAGTool.invoke(kb_ids=["report_kb"])
         → docs=[{content: "一分厂1月成本报告..."}], score=0.8

ResultAggregator.aggregate():
  rag_docs: [{content: "一分厂1月成本报告...", score: 0.8}]
  db_result: {rows: [{hr_cost: 500000, _source_db: "hr_system"},
                     {material_cost: 1200000, _source_db: "supply_chain"}],
              row_count: 2, is_aggregated: True}
  rag_quality_score: 0.8
  db_quality_score: 0.9
```

**Step 4: quality_check_node**
```
route_target = "hybrid" (Planner 决策)
quality_score = (0.8 + 0.9) / 2 = 0.85 ≥ 0.7
→ decision = "pass"
```

**Step 5: prompt_assembly_node**
```
读取 tool_results（或兼容字段）：
  RAG: "一分厂1月成本报告..."
  DB: hr_cost=500000 (来源: hr_system), material_cost=1200000 (来源: supply_chain)

组装 Prompt：
  【参考资料】
  1. 一分厂1月成本报告...（来源：report_kb，相关度：0.80）

  【数据库查询结果】
  结果行数：2
  第1行：hr_cost=500000（来源数据库：hr_system）
  第2行：material_cost=1200000（来源数据库：supply_chain）

  用户问题：一分厂一月份的人力成本和物料成本是多少？...
```

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| DAG 循环依赖 | 调度器死锁 | 拓扑排序时检测，抛出 ValueError |
| 工具调用超时 | 整体延迟增加 | 每个步骤设独立超时（如 DB 3s，RAG 2s），超时降级 |
| 部分步骤失败 | 结果不完整 | 失败步骤标记 success=False，其他步骤结果正常聚合 |
| LLM 生成错误计划 | 执行异常 | ToolDispatcher 做参数校验，异常降级到简单路由 |
| 并发资源竞争 | 数据库连接耗尽 | 限制最大并行度（如 max_concurrency=3） |
