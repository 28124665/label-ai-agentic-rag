**v2.1 P0-1 拓扑修复要点**（[graph.py#L20-L45](file:///Users/renwk/workspace/data-knowledge-api/agent/langgraph/graph.py#L20-L45)）：

1. **所有工具产出必经 evidence_fusion**：`rag_tool`/`db_tool`/`plan_executor`/`web_tool` → `evidence_fusion` → `reflection`，构建不可变 `EvidenceSnapshot`，保证 prompt_assembly/verifier/references 复用同一快照
2. **新增 answer_renderer 节点**：`hallucination` 的 `pass`/`filter` 路径先经渲染（仅输出 `supported` Claim，fail-closed），再到 observability
3. **hallucination 三分支路由**（[hallucination_decision()](file:///Users/renwk/workspace/data-knowledge-api/agent/langgraph/nodes/hallucination.py#L417-L452)）：
   - `pass`/`filter` → `answer_renderer` → `observability` → `answer_output`
   - `regenerate` → `prompt_assembly`（回环重生成，最多 2 次）
   - `reject`/`exhausted` → `observability`（跳过渲染，直接拒答/保守答案）
4. **不再有无条件 quality_check → prompt_assembly 边**，避免与条件边并行执行

### 1.2 RAGTool 内部流程

```
RAGTool.invoke(input)
│
├─[0] 参数提取 + 网关解析
│     ├─ query / top_k / kb_ids / tenant_id / similarity_threshold
│     ├─ keywords_similarity_weight (默认0.5, 向量权重=1-0.5=0.5)
│     ├─ resolver._resolve_retrieval_mode(tenant_id) → local/remote/shadow
│     └─ 空查询/空kb_ids → 返回空结果
│
├─[1] 跨语言扩展（仅 local 模式）
│     └─ rag.prompts.generator.cross_languages()
│         用 LLM 将 query 翻译成 cross_languages 列表中的语言
│         例: "供应链管理" → "supply chain management"
│
├─[2] 查询预处理
│     ├─ api.utils.query_preprocessor.preprocess_query(expanded_query)
│     │   ├─ lang_detect.detect_language() → zh-simplified/zh-traditional/en
│     │   └─ t2s.convert() → 繁转简（OpenCC + 台湾用语词汇表）
│     └─ to_langgraph_lang() → zh_CN/zh_TW/en
│
├─[3] 循环（最多 1 + MAX_INTERNAL_RETRIES=1，即最多 2 次）
│     │
│     ├─[3a] 查询重写（enable_rewrite=True 时）
│     │     ├─ analyze_query_complexity(query) → simple/boolean/multi_aspect/factual/complex
│     │     ├─ 策略选择（按 retry_count 轮转）：
│     │     │   ├─ STRATEGY_SYNONYM_REWRITE → _build_synonym_expansion()
│     │     │   │   例: "供应链" → '供应链 OR "物流链" OR "价值链"'
│     │     │   ├─ STRATEGY_SUB_QUERY_DECOMPOSE → 当前简化为同义词
│     │     │   └─ STRATEGY_HYDE → 当前简化为同义词
│     │     └─ 返回 (rewritten_query, strategy_used)
│     │
│     ├─[3b] 混合检索（gateway.retrieve）
│     │     │   异常分类捕获（§5.8）：
│     │     │   ├─ RetrievalServiceError → 空结果 + RETRIEVAL_SERVICE_ERROR
│     │     │   ├─ RetrievalAuthError → 空结果 + RETRIEVAL_AUTH
│     │     │   ├─ RetrievalDataError → 透传抛出（业务错误）
│     │     │   └─ 其他异常 → 空结果（无 error_code）
│     │     │
│     │     └─ LocalRetrieverGateway.retrieve():
│     │         ├─ BM25 全文检索（关键词权重 = keywords_similarity_weight）
│     │         ├─ 向量检索（pgvector，向量权重 = 1 - keywords_similarity_weight）
│     │         └─ 分数融合：final_score = kw_weight*bm25 + vec_weight*vector
│     │
│     ├─[3c] Rerank 精排（enable_rerank=True 且有结果时）
│     │     ├─ _get_rerank_model() → LLMBundle(RERANK 类型)
│     │     └─ multilingual_rerank(query_simplified, chunks, top_k, rerank_model)
│     │         ├─ 构造 (query_simplified, search_text) pairs
│     │         ├─ rerank_model.score_pairs(pairs) → 分数列表
│     │         ├─ 回填 rerank_score 到每个 chunk
│     │         └─ 按 rerank_score 降序截取 top_k
│     │
│     ├─[3d] 质量评估
│     │     ├─ 提取分数：rerank_score > similarity > score
│     │     ├─ top_score = max(scores)
│     │     ├─ relevant_count = count(score >= 0.5)
│     │     ├─ has_relevant = relevant_count > 0
│     │     └─ quality_score = avg(scores)
│     │
│     └─[3e] 内部重试决策
│           ├─ 条件：not has_relevant OR relevant_count < 2
│           └─ 且 attempt < 1 → continue（换策略重试）
│              否则 break
│
└─[4] 格式化输出 → RAGToolOutput
      {docs, quality_score, has_relevant, relevant_count, top_score,
       rewrite_history, query_simplified, detected_lang,
       retrieval_time_ms, retrieval_mode_used, retrieval_error_code}
```

### 1.3 DBTool 内部流程（SqlAgentRunner）

```
SqlAgentRunner.invoke(input)
│
├─[0] 参数提取
│     ├─ query / query_simplified / query_lang / tenant_id / llm_id
│     ├─ db_id / mcp_server_name / db_schema_config
│     ├─ exploration_mode: sql_agent(默认) | legacy
│     └─ exploration_hints / allowed_db_ids (来自 DataSkill)
│
├─[1] legacy 模式判断
│     └─ exploration_mode == "legacy" → 回退到 DatabaseTool.invoke()
│        （启发式规则流水线，无 LLM）
│
├─[2] MCP 会话初始化
│     ├─ runtime.load_db_config(db_schema_config)
│     ├─ runtime.init_session(tenant_id, mcp_server_name)
│     └─ 失败 → 返回 _error_result
│
├─[3] 库白名单校验（DataSkill 约束）
│     └─ db_id not in allowed_db_ids → 返回 _error_result
│
├─[4] 模板短路（enable_template=True）
│     │   优先级 ②：确定性知识路径，零 LLM 开销
│     ├─ TemplateMatcher.match(query) → 匹配 query_templates.yaml
│     │   ├─ 未命中 → 返回 None，继续探索
│     │   └─ 命中 → 
│     │       ├─ validate_sql(sql) 安全校验
│     │       ├─ execute_sql(db_id, sql)
│     │       └─ 返回 db_result（source="template", quality=1.0/0.0）
│     └─ 失败 → 降级到 SQL Agent
│
├─[5] LLM callable 构建
│     ├─ 预检：_resolve_chat_model(tenant_id, llm_id)
│     │   失败 → 返回 None → 降级到 legacy 流水线
│     └─ 构建 async llm_callable(prompt) -> str
│         内部走 ModelGateway.async_chat()
│
├─[6] SQL Agent 子图探索（优先级 ③）
│     │   预算：ExplorationBudget（max_steps/llm_calls/sql_execs）
│     │
│     └─ SqlAgentSubgraph.run()：有界 ReAct 循环
│         │
│         │  ┌──────────────────────────────────────────┐
│         │  │  budget_guard → agent_llm ⇄ tool_exec    │
│         │  │                  → finalize → END        │
│         │  └──────────────────────────────────────────┘
│         │
│         ├─[6a] budget_guard（每步前置检查）
│         │   ├─ step_count >= max_steps → VERDICT_BUDGET_EXHAUSTED
│         │   ├─ llm_call_count >= max_llm_calls → 同上
│         │   └─ sql_exec_count >= max_sql_execs → 同上
│         │
│         ├─[6b] agent_llm（LLM 思考）
│         │   ├─ 构建 step_prompt（含 query + observations + 工具列表）
│         │   ├─ llm_callable(prompt) → JSON action
│         │   ├─ parse_agent_action() → {action, args}
│         │   │   解析失败 → _parse_failures++，最多 2 次容错
│         │   └─ action 类型：
│         │       ├─ list_databases → 列出可用数据库
│         │       ├─ list_tables → 列出表
│         │       ├─ describe_table → 表结构
│         │       ├─ execute_sql → 执行 SQL（核心）
│         │       ├─ finish → 终止（找到数据）
│         │       └─ give_up → 终止（放弃探索）
│         │
│         ├─[6c] tool_exec（工具执行）
│         │   ├─ SqlAgentToolset 分发到对应工具
│         │   ├─ execute_sql 工具含护栏：
│         │   │   ├─ SQL 安全校验（防注入/DDL/危险操作）
│         │   │   ├─ 行数限制（max_result_rows）
│         │   │   └─ 执行结果 → Observation
│         │   └─ 工具错误 → 作为 Observation 回传（自愈输入）
│         │
│         └─[6d] finalize（终态判定）
│             ├─ finish + 有数据 → VERDICT_DATA_FOUND (quality=1.0)
│             ├─ finish + 无数据 → VERDICT_NO_DATA_CONFIRMED (quality=0.5)
│             ├─ give_up → VERDICT_EXPLORATION_FAILED (quality=0.0)
│             └─ budget 耗尽 → VERDICT_BUDGET_EXHAUSTED (quality=0.0)
│
└─[7] 组装 db_result
      {sql, rows, row_count, source="sql_agent", quality_score,
       exploration_verdict, exploration_stats, step_trace,
       finish_summary, give_up_reason, formatted_result, ...}
```

### 1.4 质量检查决策流程

```
quality_check_node(state)
│
├─[1] chitchat 模式 → 直接 pass
│
├─[2] DB 探索终态优先判定（exploration_verdict 非空时）
│     ├─ data_found → pass
│     ├─ no_data_confirmed → pass（LLM 确认无数据，不重试）
│     ├─ exploration_failed → retry_db (retry<max) / fallback_web
│     └─ budget_exhausted → fallback_web（重试无意义）
│
├─[3] RAG infra 失败前置规则
│     └─ retrieval_error_code in {RETRIEVAL_SERVICE_ERROR, RETRIEVAL_AUTH}
│        → fallback_web（重试挂掉的服务无意义）
│
├─[4] 质量阈值判定
│     ├─ database: score >= 0.7 且 row_count > 0 → pass
│     ├─ rag/hybrid: score >= 0.7 且 has_relevant 且 relevant_count >= 2 → pass
│     └─ 未达标 → 进入重试决策
│
└─[5] 重试决策
      ├─ retry_count < max_retries(3) → retry_rag / retry_db
      └─ 超限 → fallback_web
```

### 1.5 幻觉检测处置流程（v2.1 §4.0.2 Claim 级可追溯 + v3.0 PairVerifier 分层验证）

```
hallucination_node(state)                                  [hallucination.py]
│
├─[0] 解析 run_mode / enforcement_mode
│     ├─ 优先用 state 中已注入值（intent_router 写入）
│     └─ 缺失时从 agent_config + route_target 现场解析
│         EnforcementMode: ENFORCED（事实型 fail-closed）/ DISABLED / SHADOW
│
├─[1] 前置 fail-closed 拦截（P0-3 修复）
│     ├─ 空答案 → ENFORCED reject("无法生成答案") / DISABLED·SHADOW pass
│     ├─ 无 Evidence → ENFORCED reject("当前资料不足以确认") / DISABLED·SHADOW pass
│     └─ feature flag 关闭 → pass（返回值标注 enforcement_mode）
│
├─[2] AST 解析失败处理（★ P0-3 关键：堵住 ENFORCED 逃逸口）
│     └─ ENFORCED + answer_ast 缺失：
│        ├─ regenerate_count >= MAX_REGENERATES(2) → reject("答案结构解析失败")
│        └─ 否则 → regenerate（回 prompt_assembly 重新生成结构化答案）
│     DISABLED/SHADOW：fall through 到 VerifierGateway 纯文本验证
│
├─[3] ENFORCED + AST 可用：Claim 级三层验证闭环（v3.0 主路径）
│     │
│     ├─[3a] 构建 EvidenceSnapshot
│     │       EvidenceSnapshot.build(raw_evidence)
│     │       → 不可变快照（含 snapshot_id，与 prompt_assembly 复用同一份）
│     │
│     ├─[3b] 反序列化 Claim 列表（来自 answer_ast）
│     │       无 Claim → 降级走 VerifierGateway
│     │
│     ├─[3c] 构建 PairVerifier（batch_size=5）
│     │       注入 VerificationBudget（max_llm_calls 等限制）
│     │
│     ├─[3d] CitationBinder.bind_async(claims, answer_with_citations)
│     │       9 步闭环（[citation_binder.py]）：
│     │       1. Claim 数量预算（超 max_claims → TRUNCATED）
│     │       2. 解析模型声明的引用编号 [1][2]...（保留 raw_declared_indices）
│     │       3. 分类保存（P0-4）：
│     │          - resolved_declared_ids（合法且授权）
│     │          - invalid_indices（如 [999] 越界）
│     │          - unauthorized_ids（越权引用）
│     │       4. 引用数量预算截断（max_references_per_claim）
│     │       5. 收集所有 Claim-Evidence pair → PairVerifier.verify_pairs() batch
│     │          三层验证（Rule + NLI + LLM，短路策略）：
│     │          - 规则层：实体提取 + 容差匹配 + 矛盾判定
│     │          - NLI 层：LLM 推理 entailment/neutral/contradiction
│     │          - LLM 层：语义支持度判断
│     │       6. 回填 PairVerdict 到各 Claim（P0-5：每个 pair 独立状态）
│     │       7. 反证扫描（P0-8）：扫描整个 snapshot 找未声明的冲突证据
│     │          → 写入 contradicting_ids，不计入模型引用
│     │       8. 联合证据蕴含（P0-8）：多 Evidence 联合证明一个 Claim
│     │       9. 按 pair 聚合 verifier_status（不再无条件 ok）
│     │
│     ├─[3e] VerdictMatrix.evaluate(claims)
│     │       强类型规则 DSL（启动时校验字段/枚举/默认规则唯一性）
│     │       优先级：verifier_error > contradicted > insufficient > supported
│     │       → 每个 Claim 的 final_status
│     │
│     ├─[3f] PolicyEngine.decide(claims, claim_verdicts, enforcement_mode)
│     │       唯一决策者（[policy_engine.py]）：
│     │       - 计算加权 faithfulness_score
│     │       - 关键 Claim 单条矛盾/不足 → 立即 reject（不数量比）
│     │       - 验证器大面积故障 → fail-closed reject
│     │       - 输出 action: pass/filter/regenerate/reject
│     │
│     └─[3g] 异常 → ENFORCED fail-closed reject("验证服务异常")
│
├─[4] DISABLED/SHADOW 路径：VerifierGateway 三层验证（legacy）
│     ├─ verifier.verify_faithfulness(answer, context, query)
│     │   规则层 0.4 + NLI 层 0.4 + LLM 层 0.2 → faithfulness_score
│     ├─ 异常 → DISABLED/SHADOW 降级字符重叠度（_verify_faithfulness）
│     └─ ENFORCED 已在 [3] 处理，此处仅 DISABLED/SHADOW
│
├─[5] 分级处置 _dispose(score, regenerate_count)
│     ├─ score >= 0.85 → pass
│     ├─ 0.6 <= score < 0.85 → filter
│     ├─ 0.3 <= score < 0.6 → regenerate（regenerate_count >= 2 → exhausted）
│     └─ score < 0.3 → reject
│
└─[6] hallucination_decision() 条件路由
      ├─ pass / filter → answer_renderer（仅输出 supported Claim，fail-closed）
      │                  → observability → answer_output → END
      ├─ regenerate → prompt_assembly（回环，最多 2 次）
      └─ reject / exhausted → observability（跳过渲染）
                               → answer_output（拒答/保守答案）→ END
```

**与旧版差异**：
- 旧版三层验证（规则 0.4 + NLI 0.4 + LLM 0.2）→ 保留为 DISABLED/SHADOW 路径
- 新增 ENFORCED 主路径：Claim 级可追溯 + PairVerifier batch + VerdictMatrix + PolicyEngine
- 旧版四级处置直连 observability → 新版 pass/filter 先经 answer_renderer 过滤未验证 Claim
- 旧版 AST 解析失败降级纯文本 → 新版 ENFORCED 模式 fail-closed 重试/拒答

### 1.6 Evidence Fusion 节点流程（v2.1 §4.1 P0-2 修复 + 任务二建议 6）

```
evidence_fusion_node(state)                                [evidence_fusion.py]
│
├─[1] 从工具结果重新标准化 Evidence（★ P0-2：每次都重建，不再只在 evidence 为空时补充）
│     ├─ rag_docs → normalize_tool_result("rag_search")
│     ├─ db_result → normalize_tool_result("db_query")
│     └─ web_docs → normalize_tool_result("web_search")
│     → 每条 Evidence 含 source_type / evidence_id / content / metadata.tool_run_id
│
├─[2] 与旧 evidence 合并（★ P0-2：基于 (source_type, tool_run_id) 精确替换）
│     _merge_with_replacement(old, new):
│     ├─ 新证据优先，记录 replaced_keys = {(source_type, tool_name)}
│     ├─ 保留未被替换的旧证据（未参与本轮重试的工具）
│     └─ 替换规则：
│        - 同 source_type + 同 tool_run_id 前缀 → 旧证据整体失效
│        - 不同 source_type → 累积（RAG + DB + Web 共存）
│        - 同 source_type 不同 tool_run_id → 累积（多次 RAG 不同 query 共存）
│
├─[3] 来源配额（任务二建议 6，避免 DB 行级证据挤掉反证）
│     _apply_source_quota(evidences, quota):
│     ├─ 按 source_type 分组
│     ├─ 每组按 _evidence_weight 降序排序
│     └─ 截取配额：rag:10 / db:10 / web:5 / report:5（可 agent_config 覆盖）
│
├─[4] 融合去重排序
```

4. **质量阈值判定**：database 需 score≥0.7 且 row_count>0；rag/hybrid 需 score≥0.7 且 has_relevant 且 relevant_count≥2
5. **重试决策**：retry_count<max_retries(3) → retry_rag/retry_db；超限 → fallback_web

## DB 工具的两个关键问题


### 一、模式判断（exploration_mode）的作用

#### 1.1 两种模式

[runner.py#L57-L59](file:///Users/renwk/workspace/data-knowledge-api/agent/langgraph/tools/sql_agent/runner.py#L57-L59)

```python
MODE_SQL_AGENT = "sql_agent"  # 默认：LLM 驱动的 ReAct 探索
MODE_LEGACY = "legacy"        # 应急回滚：启发式规则流水线
```

#### 1.2 各自做什么

**sql_agent 模式**（默认）：
```
用户问题 → LLM 思考 → 选工具 → 执行 → 观察结果 → 再思考 → ...
```
- 模板短路 → SQL Agent ReAct 子图 → 终态
- 能处理任意复杂查询，但依赖 LLM 可用

**legacy 模式**：
```
用户问题 → 正则/规则提取 → 模板匹配 → 直接执行
```
- 启发式规则流水线（[database_tool.py](file:///Users/renwk/workspace/data-knowledge-api/agent/langgraph/tools/database_tool.py)）
- 零 LLM 开销，但只能处理预定义模式

#### 1.3 模式判断的三大作用

**作用 1：应急回滚开关**

[runner.py#L131-L133](file:///Users/renwk/workspace/data-knowledge-api/agent/langgraph/tools/sql_agent/runner.py#L131-L133)

```python
if exploration_mode == MODE_LEGACY:
    logger.info("[SqlAgentRunner] exploration_mode=legacy，回滚到启发式规则流水线")
    return await get_database_tool().invoke(input_data)
```

当 LLM 服务故障、SQL Agent 子图频繁出错、或需要快速验证时，**一行配置即可整体回滚**到无 LLM 的规则流水线，保证数据库查询能力不中断。

**作用 2：成本控制**

legacy 模式零 LLM 调用，适合：
- 高频固定模式查询（如每分钟上百次的运营看板查询）
- 对延迟极度敏感的场景
- 成本敏感的批量任务

**作用 3：灰度发布的切换器**

```yaml
# conf/sql_agent.yaml
exploration_mode: sql_agent  # 全量 sql_agent
# exploration_mode: legacy   # 全量 legacy
```

上线时可以按租户/场景切换模式，实现灰度发布。

#### 1.4 配置优先级

[runner.py#L120-L123](file:///Users/renwk/workspace/data-knowledge-api/agent/langgraph/tools/sql_agent/runner.py#L120-L123)

```python
exploration_mode = input_data.get(
    "exploration_mode",                                      # 1. 请求级覆盖（最高）
    self._file_config.get("exploration_mode", MODE_SQL_AGENT) # 2. 文件配置
)                                                            # 3. 代码默认值（最低）
```

| 优先级 | 来源 | 适用场景 |
|--------|------|---------|
| 1（最高） | 请求参数 `input_data["exploration_mode"]` | 按租户/场景动态切换 |
| 2 | `conf/sql_agent.yaml` | 全局默认配置 |
| 3（最低） | 代码常量 `MODE_SQL_AGENT` | 兜底默认 |

**Java 类比**：类似 Spring Profile + `@ConditionalOnProperty`，通过配置开关切换 Bean 实现。

#### 1.5 自动降级链（重要）

模式判断不只是"二选一"，还有**自动降级**：

```
sql_agent 模式（默认）
    │
    ├─ LLM 配置不可用 → 自动降级到 legacy
    │  [runner.py#L166-L171]
    │
    └─ SQL Agent 子图执行异常 → 自动降级到 legacy
       [runner.py#L193-L195]
```

也就是说，即使配置成 `sql_agent`，当 LLM 不可用或子图异常时，**自动回退到 legacy 流水线**，不会让查询失败。

### 二、MCP 会话初始化的时机

#### 2.1 MCP 是什么

MCP（Model Context Protocol）是本项目用于**数据库连接管理**的抽象层。[db_runtime.py](file:///Users/renwk/workspace/data-knowledge-api/agent/langgraph/tools/db_runtime.py) 封装了数据库连接池、SQL 执行、schema 发现等能力。

**MCP 会话**：一次数据库连接会话，包含连接池、可用数据库列表、表结构缓存等。

#### 2.2 初始化时机

[runner.py#L135-L144](file:///Users/renwk/workspace/data-knowledge-api/agent/langgraph/tools/sql_agent/runner.py#L135-L144)

```python
# 1. 加载配置并初始化 MCP 会话（共享 DbRuntime）
self._runtime.load_db_config(db_schema_config)  # 加载库 schema 配置
try:
    self._runtime.init_session(tenant_id, mcp_server_name)  # 初始化会话
except Exception as e:
    logger.error(f"[SqlAgentRunner] MCP 会话初始化失败: {e}")
    return self._error_result(start_time, f"MCP 会话初始化失败: {e}")

if not self._runtime.db_tools:
    return self._error_result(start_time, "未从 MCP Server 获取到任何数据库工具")
```

**初始化时机**：**每次 `SqlAgentRunner.invoke()` 调用时**，在模式判断之后、模板短路之前。

#### 2.3 完整时序

```
SqlAgentRunner.invoke(input)
    │
    ├─[1] 模式判断（legacy 直接返回，不初始化 MCP）
    │
    ├─[2] MCP 会话初始化 ← 这里！
    │     ├─ load_db_config() 加载 conf/db_schema.yaml
    │     └─ init_session() 建立连接
    │
    ├─[3] 库白名单校验
    ├─[4] 模板短路
    ├─[5] LLM callable 构建
    └─[6] SQL Agent 子图探索
```

**关键点**：
- **legacy 模式跳过 MCP 初始化**（直接走 `get_database_tool().invoke()`，有自己独立的连接逻辑）
- **MCP 初始化在模板短路之前**，因为模板短路也需要执行 SQL，需要数据库连接

#### 2.4 init_session 做了什么

`DbRuntime.init_session(tenant_id, mcp_server_name)` 的作用：

1. **建立数据库连接池**：根据 `tenant_id` 获取该租户的数据库配置（host/port/user/password）
2. **加载 MCP Server 工具**：从 MCP Server 获取可用的数据库工具集（`list_databases`、`describe_table`、`execute_sql` 等），存入 `self._runtime.db_tools`
3. **缓存 schema 信息**：可选的表结构预加载，加速后续 `describe_table` 调用

#### 2.5 共享 DbRuntime 设计

[runner.py#L80](file:///Users/renwk/workspace/data-knowledge-api/agent/langgraph/tools/sql_agent/runner.py#L80)

```python
def __init__(self, runtime: Optional[DbRuntime] = None, ...):
    self._runtime = runtime or get_db_runtime()  # 进程级单例
```

- `DbRuntime` 是**进程级单例**，多个 `SqlAgentRunner` 实例共享
- 每次调用 `init_session()` 是**会话级初始化**（按 tenant_id 区分），不是重新创建连接池
- 类似 Java 的 `DataSource` + `Connection`：DataSource 是单例，Connection 是按需获取

#### 2.6 何时销毁

MCP 会话**不在 invoke 结束时销毁**，而是由 `DbRuntime` 单例管理生命周期，随进程退出而清理。这样设计的好处：
- 避免频繁建连/断连的开销
- 连接池可复用，提升性能
- 多请求共享 schema 缓存
