### 1.2 RAGTool 内部流程

```
RAGTool.invoke(input)
│
├─[0] 参数提取 + 网关解析
│     ├─ query / top_k / kb_ids / tenant_id / similarity_threshold
│     ├─ keywords_similarity_weight (默认0.5, 向量权重=1-0.5=0.5)
│     ├─ resolver._resolve_retrieval_mode(tenant_id) → local/remote/shadow
│     └─ 空查询/空kb_ids → 返回空结果
│
├─[1] 跨语言扩展（仅 local 模式）
│     └─ rag.prompts.generator.cross_languages()
│         用 LLM 将 query 翻译成 cross_languages 列表中的语言
│         例: "供应链管理" → "supply chain management"
│
├─[2] 查询预处理
│     ├─ api.utils.query_preprocessor.preprocess_query(expanded_query)
│     │   ├─ lang_detect.detect_language() → zh-simplified/zh-traditional/en
│     │   └─ t2s.convert() → 繁转简（OpenCC + 台湾用语词汇表）
│     └─ to_langgraph_lang() → zh_CN/zh_TW/en
│
├─[3] 循环（最多 1 + MAX_INTERNAL_RETRIES=1，即最多 2 次）
│     │
│     ├─[3a] 查询重写（enable_rewrite=True 时）
│     │     ├─ analyze_query_complexity(query) → simple/boolean/multi_aspect/factual/complex
│     │     ├─ 策略选择（按 retry_count 轮转）：
│     │     │   ├─ STRATEGY_SYNONYM_REWRITE → _build_synonym_expansion()
│     │     │   │   例: "供应链" → '供应链 OR "物流链" OR "价值链"'
│     │     │   ├─ STRATEGY_SUB_QUERY_DECOMPOSE → 当前简化为同义词
│     │     │   └─ STRATEGY_HYDE → 当前简化为同义词
│     │     └─ 返回 (rewritten_query, strategy_used)
│     │
│     ├─[3b] 混合检索（gateway.retrieve）
│     │     │   异常分类捕获（§5.8）：
│     │     │   ├─ RetrievalServiceError → 空结果 + RETRIEVAL_SERVICE_ERROR
│     │     │   ├─ RetrievalAuthError → 空结果 + RETRIEVAL_AUTH
│     │     │   ├─ RetrievalDataError → 透传抛出（业务错误）
│     │     │   └─ 其他异常 → 空结果（无 error_code）
│     │     │
│     │     └─ LocalRetrieverGateway.retrieve():
│     │         ├─ BM25 全文检索（关键词权重 = keywords_similarity_weight）
│     │         ├─ 向量检索（pgvector，向量权重 = 1 - keywords_similarity_weight）
│     │         └─ 分数融合：final_score = kw_weight*bm25 + vec_weight*vector
│     │
│     ├─[3c] Rerank 精排（enable_rerank=True 且有结果时）
│     │     ├─ _get_rerank_model() → LLMBundle(RERANK 类型)
│     │     └─ multilingual_rerank(query_simplified, chunks, top_k, rerank_model)
│     │         ├─ 构造 (query_simplified, search_text) pairs
│     │         ├─ rerank_model.score_pairs(pairs) → 分数列表
│     │         ├─ 回填 rerank_score 到每个 chunk
│     │         └─ 按 rerank_score 降序截取 top_k
│     │
│     ├─[3d] 质量评估
│     │     ├─ 提取分数：rerank_score > similarity > score
│     │     ├─ top_score = max(scores)
│     │     ├─ relevant_count = count(score >= 0.5)
│     │     ├─ has_relevant = relevant_count > 0
│     │     └─ quality_score = avg(scores)
│     │
│     └─[3e] 内部重试决策
│           ├─ 条件：not has_relevant OR relevant_count < 2
│           └─ 且 attempt < 1 → continue（换策略重试）
│              否则 break
│
└─[4] 格式化输出 → RAGToolOutput
      {docs, quality_score, has_relevant, relevant_count, top_score,
       rewrite_history, query_simplified, detected_lang,
       retrieval_time_ms, retrieval_mode_used, retrieval_error_code}
```

### 1.3 DBTool 内部流程（SqlAgentRunner）

```
SqlAgentRunner.invoke(input)
│
├─[0] 参数提取
│     ├─ query / query_simplified / query_lang / tenant_id / llm_id
│     ├─ db_id / mcp_server_name / db_schema_config
│     ├─ exploration_mode: sql_agent(默认) | legacy
│     └─ exploration_hints / allowed_db_ids (来自 DataSkill)
│
├─[1] legacy 模式判断
│     └─ exploration_mode == "legacy" → 回退到 DatabaseTool.invoke()
│        （启发式规则流水线，无 LLM）
│
├─[2] MCP 会话初始化
│     ├─ runtime.load_db_config(db_schema_config)
│     ├─ runtime.init_session(tenant_id, mcp_server_name)
│     └─ 失败 → 返回 _error_result
│
├─[3] 库白名单校验（DataSkill 约束）
│     └─ db_id not in allowed_db_ids → 返回 _error_result
│
├─[4] 模板短路（enable_template=True）
│     │   优先级 ②：确定性知识路径，零 LLM 开销
│     ├─ TemplateMatcher.match(query) → 匹配 query_templates.yaml
│     │   ├─ 未命中 → 返回 None，继续探索
│     │   └─ 命中 → 
│     │       ├─ validate_sql(sql) 安全校验
│     │       ├─ execute_sql(db_id, sql)
│     │       └─ 返回 db_result（source="template", quality=1.0/0.0）
│     └─ 失败 → 降级到 SQL Agent
│
├─[5] LLM callable 构建
│     ├─ 预检：_resolve_chat_model(tenant_id, llm_id)
│     │   失败 → 返回 None → 降级到 legacy 流水线
│     └─ 构建 async llm_callable(prompt) -> str
│         内部走 ModelGateway.async_chat()
│
├─[6] SQL Agent 子图探索（优先级 ③）
│     │   预算：ExplorationBudget（max_steps/llm_calls/sql_execs）
│     │
│     └─ SqlAgentSubgraph.run()：有界 ReAct 循环
│         │
│         │  ┌──────────────────────────────────────────┐
│         │  │  budget_guard → agent_llm ⇄ tool_exec    │
│         │  │                  → finalize → END        │
│         │  └──────────────────────────────────────────┘
│         │
│         ├─[6a] budget_guard（每步前置检查）
│         │   ├─ step_count >= max_steps → VERDICT_BUDGET_EXHAUSTED
│         │   ├─ llm_call_count >= max_llm_calls → 同上
│         │   └─ sql_exec_count >= max_sql_execs → 同上
│         │
│         ├─[6b] agent_llm（LLM 思考）
│         │   ├─ 构建 step_prompt（含 query + observations + 工具列表）
│         │   ├─ llm_callable(prompt) → JSON action
│         │   ├─ parse_agent_action() → {action, args}
│         │   │   解析失败 → _parse_failures++，最多 2 次容错
│         │   └─ action 类型：
│         │       ├─ list_databases → 列出可用数据库
│         │       ├─ list_tables → 列出表
│         │       ├─ describe_table → 表结构
│         │       ├─ execute_sql → 执行 SQL（核心）
│         │       ├─ finish → 终止（找到数据）
│         │       └─ give_up → 终止（放弃探索）
│         │
│         ├─[6c] tool_exec（工具执行）
│         │   ├─ SqlAgentToolset 分发到对应工具
│         │   ├─ execute_sql 工具含护栏：
│         │   │   ├─ SQL 安全校验（防注入/DDL/危险操作）
│         │   │   ├─ 行数限制（max_result_rows）
│         │   │   └─ 执行结果 → Observation
│         │   └─ 工具错误 → 作为 Observation 回传（自愈输入）
│         │
│         └─[6d] finalize（终态判定）
│             ├─ finish + 有数据 → VERDICT_DATA_FOUND (quality=1.0)
│             ├─ finish + 无数据 → VERDICT_NO_DATA_CONFIRMED (quality=0.5)
│             ├─ give_up → VERDICT_EXPLORATION_FAILED (quality=0.0)
│             └─ budget 耗尽 → VERDICT_BUDGET_EXHAUSTED (quality=0.0)
│
└─[7] 组装 db_result
      {sql, rows, row_count, source="sql_agent", quality_score,
       exploration_verdict, exploration_stats, step_trace,
       finish_summary, give_up_reason, formatted_result, ...}
```

### 1.4 质量检查决策流程

```
quality_check_node(state)
│
├─[1] chitchat 模式 → 直接 pass
│
├─[2] DB 探索终态优先判定（exploration_verdict 非空时）
│     ├─ data_found → pass
│     ├─ no_data_confirmed → pass（LLM 确认无数据，不重试）
│     ├─ exploration_failed → retry_db (retry<max) / fallback_web
│     └─ budget_exhausted → fallback_web（重试无意义）
│
├─[3] RAG infra 失败前置规则
│     └─ retrieval_error_code in {RETRIEVAL_SERVICE_ERROR, RETRIEVAL_AUTH}
│        → fallback_web（重试挂掉的服务无意义）
│
├─[4] 质量阈值判定
│     ├─ database: score >= 0.7 且 row_count > 0 → pass
│     ├─ rag/hybrid: score >= 0.7 且 has_relevant 且 relevant_count >= 2 → pass
│     └─ 未达标 → 进入重试决策
│
└─[5] 重试决策
      ├─ retry_count < max_retries(3) → retry_rag / retry_db
      └─ 超限 → fallback_web
```

### 1.5 幻觉检测处置流程

```
hallucination_node(state)
│
├─[1] 论断拆解（Claim Decomposition）
│     ├─ 句子边界拆分
│     ├─ 复合句拆分（虽然/但是/因为）
│     ├─ 列表项拆分
│     └─ 数值论断合并（避免"2024年Q3"+"营收15%"拆散）
│
├─[2] 三层验证（每条 claim）
│     │
│     ├─ 规则层（权重 0.4）—— fact_checker.py
│     │   ├─ 实体提取：date/ratio/currency/number/proper_noun
│     │   ├─ 实体匹配（容差：数值±0.1%，百分比±0.5%）
│     │   ├─ 矛盾判定 → CONTRADICTED (0.0)
│     │   ├─ 无匹配 → NOT_SUPPORTED (0.3)
│     │   └─ 全匹配 → SUPPORTED (1.0)
│     │
│     ├─ NLI 层（权重 0.4）—— LLM 推理
│     │   ├─ entailment → 1.0
│     │   ├─ neutral → 0.5
│     │   └─ contradiction → 0.0
│     │
│     └─ LLM 层（权重 0.2）—— 语义支持度
│         ├─ SUPPORTED → 1.0
│         ├─ NOT_SUPPORTED → 0.3
│         └─ CONTRADICTED → 0.0
│
│   短路优化：
│     ├─ 规则层 CONTRADICTED → 立即停止，score=0.0
│     └─ 规则层 SUPPORTED + 有精确实体 → 跳过 LLM，score=1.0
│
├─[3] 加权投票
│     score = 0.4*rule + 0.4*nli + 0.2*llm
│     矛盾降级：任一 claim 规则层矛盾 → 整体 score 上限 0.5
│     长度加权：长论断权重更高
│
└─[4] 四级处置
      ├─ score >= 0.85 → pass → observability → answer_output
      ├─ 0.6 <= score < 0.85 → filter → 过滤不支持论断 → answer_output
      ├─ 0.3 <= score < 0.6 → regenerate → 回 prompt_assembly（最多2次）
      └─ score < 0.3 → reject → answer_output（拒答）
          regenerate 用尽 → exhausted → 保守答案
```

## 二、文字详解版

### 阶段 0：API 入口

**接口**：`POST /v1/conversation/langgraph_completion`

接收 `user_question`、`kb_ids`、`db_id`、`conversation_history`、`agent_config`，调用 `LangGraphRunner.arun_with_checkpointer()` 启动状态图，通过 SSE 流式返回。

### 阶段 1：question_input 节点

[user_question.py](file:///Users/renwk/workspace/data-knowledge-api/agent/langgraph/nodes/user_question.py) 初始化 `AgentState`，注入用户问题、租户 ID、知识库 ID、对话历史等基础字段。

### 阶段 2：intent_router 节点（4 层递进 + Skill 解析）

[intent_router.py](file:///Users/renwk/workspace/data-knowledge-api/agent/langgraph/nodes/intent_router.py) 执行：

**2.1 路由决策**（4 层递进）
- **L0 前置过滤**（[pre_filter.py](file:///Users/renwk/workspace/data-knowledge-api/agent/langgraph/routers/pre_filter.py)，<1ms）：安全拦截（SQL 注入/越权）、问候语识别、实体格式匹配（SKU-xxx）
- **L1 规则路由**（[rule_router.py](file:///Users/renwk/workspace/data-knowledge-api/agent/langgraph/routers/rule_router.py)，<10ms）：范围词判断、时效性检测、RAG/DB 偏向词打分，置信度 ≥0.7 直接返回
- **L2 LLM 路由**（[llm_router.py](file:///Users/renwk/workspace/data-knowledge-api/agent/langgraph/routers/llm_router.py)，<300ms）：qwen3.5-9B 结构化 JSON 输出，含熔断器（3 次失败/60s 恢复）和超时降级
- **L3 Planner**（[planner.py](file:///Users/renwk/workspace/data-knowledge-api/agent/langgraph/routers/planner.py)，<5s）：qwen3.6-27B 生成 DAG 执行计划

**2.2 Skill 解析**（[resolver.py](file:///Users/renwk/workspace/data-knowledge-api/agent/langgraph/skills/resolver.py)）

当 `_should_resolve_skill()` 返回 True（显式指定 report_type/skill_id，或 complexity=complex，或文本含"报告/skill"）时触发，6 级降级链：
1. `skill_id` 显式指定 → `registry.get_by_id()`
2. `report_type` → `registry.get_report_by_type()`（精确字符串匹配）
3. `intent_keywords` 关键词匹配（按字符数取最大）
4. `tenant_defaults` 租户默认
5. `default_skill_id` 全局默认
6. `generic_analysis` 系统兜底

解析成功后反向链接 DataSkill 和 RetrievalSkill，写入 `state["skill_set"]`。

**2.3 条件路由**（[route_decision()](file:///Users/renwk/workspace/data-knowledge-api/agent/langgraph/nodes/intent_router.py#L284-L359)）

优先级：`needs_clarification` → `react_subgraph`（ReAct 启用+complex）→ `plan_executor`（planner+complex）→ `rag_tool`/`db_tool`（含 hybrid 降级处理）→ `prompt_assembly`（chitchat）。

### 阶段 3：工具执行层

#### 3.1 RAG 工具（[rag_tool.py](file:///Users/renwk/workspace/data-knowledge-api/agent/langgraph/tools/rag_tool.py)）

**完整内部流程**：

1. **跨语言扩展**（仅 local 模式）：调用 `rag.prompts.generator.cross_languages()`，用 LLM 将 query 翻译为目标语言（如繁体→简体→英文），扩大召回面。

2. **查询预处理**（[query_preprocessor.py](file:///Users/renwk/workspace/data-knowledge-api/api/utils/query_preprocessor.py)）：
   - 语言检测（[lang_detect.py](file:///Users/renwk/workspace/data-knowledge-api/rag/nlp/lang_detect.py)）：基于字符比例统计，返回 `zh-simplified`/`zh-traditional`/`en`
   - 繁简转换（[t2s.py](file:///Users/renwk/workspace/data-knowledge-api/rag/nlp/t2s.py)）：OpenCC 字形转换 + 台湾用语词汇表（伺服器→服务器）+ 专有名词白名单保护

3. **查询重写 + 检索 + Rerank 循环**（最多 2 次）：
   - **查询重写**（[query_rewriter.py](file:///Users/renwk/workspace/data-knowledge-api/agent/component/query_rewriter.py)）：`analyze_query_complexity()` 判断复杂度（simple/boolean/multi_aspect/factual/complex），按 retry_count 轮转策略（synonym_rewrite / sub_query_decompose / hyde），当前 sub_query 和 hyde 简化为同义词扩展
   - **混合检索**（[local_retriever.py](file:///Users/renwk/workspace/data-knowledge-api/agent/langgraph/gateways/local_retriever.py)）：BM25 全文检索（权重 = `keywords_similarity_weight`）+ 向量检索 pgvector（权重 = 1 - `keywords_similarity_weight`），分数融合后返回 chunks
   - **异常分类捕获**：`RetrievalServiceError`（超时/5xx/熔断）→ 空结果 + error_code；`RetrievalAuthError`（401/403）→ 空结果 + error_code；`RetrievalDataError`（业务错误）→ 透传抛出
   - **多语言 Rerank**（[multilingual_reranker.py](file:///Users/renwk/workspace/data-knowledge-api/api/utils/multilingual_reranker.py)）：构造 `(query_simplified, search_text)` pairs，调用 rerank 模型 `score_pairs()`，回填 `rerank_score`，按分数降序截取 top_k。无 rerank 模型时跳过，按原顺序返回
   - **质量评估**：提取分数（优先 rerank_score > similarity > score），计算 top_score、relevant_count（score≥0.5）、has_relevant、quality_score（平均分）
   - **内部重试决策**：`not has_relevant` 或 `relevant_count < 2` 且 `attempt < 1` → 换策略重试

4. **输出**：`RAGToolOutput`（docs, quality_score, has_relevant, relevant_count, top_score, rewrite_history, query_simplified, detected_lang, retrieval_time_ms, retrieval_mode_used, retrieval_error_code）

#### 3.2 DB 工具（[sql_agent/runner.py](file:///Users/renwk/workspace/data-knowledge-api/agent/langgraph/tools/sql_agent/runner.py)）

**完整内部流程**：

1. **模式判断**：`exploration_mode == "legacy"` → 回退到启发式规则流水线（[database_tool.py](file:///Users/renwk/workspace/data-knowledge-api/agent/langgraph/tools/database_tool.py)），无 LLM 开销

2. **MCP 会话初始化**：`DbRuntime.load_db_config()` 加载库 schema，`init_session()` 建立数据库连接，获取数据库工具集

3. **库白名单校验**：DataSkill 的 `allowed_db_ids` 约束，防止越权访问

4. **模板短路**（[TemplateMatcher](file:///Users/renwk/workspace/data-knowledge-api/agent/langgraph/tools/database_tool.py)）：
   - 匹配 `query_templates.yaml` 中的预定义 SQL 模板
   - 命中 → `validate_sql()` 安全校验 → `execute_sql()` 执行 → 返回结果（source="template", quality=1.0/0.0）
   - 未命中/校验失败/执行失败 → 降级到 SQL Agent

5. **LLM callable 构建**：预检 Chat 模型配置可用性，不可用 → 降级到 legacy 流水线；可用 → 构建 `async llm_callable(prompt) -> str`，内部走 `ModelGateway.async_chat()`

6. **SQL Agent 子图探索**（[subgraph.py](file:///Users/renwk/workspace/data-knowledge-api/agent/langgraph/tools/sql_agent/subgraph.py)）——有界 ReAct 循环：
   - **budget_guard**（每步前置检查）：step_count/llm_call_count/sql_exec_count 任一超限 → `VERDICT_BUDGET_EXHAUSTED`
   - **agent_llm**（LLM 思考）：构建 step_prompt（含 query + observations + 工具列表 + exploration_hints），LLM 输出 JSON action，`parse_agent_action()` 解析（最多 2 次解析容错）
   - **tool_exec**（工具执行）：`SqlAgentToolset` 分发到 `list_databases`/`list_tables`/`describe_table`/`execute_sql`/`finish`/`give_up`，`execute_sql` 含护栏（SQL 安全校验、行数限制），工具错误作为 Observation 回传（自愈输入）
   - **finalize**（终态判定）：
     - `finish` + 有数据 → `VERDICT_DATA_FOUND` (quality=1.0)
     - `finish` + 无数据 → `VERDICT_NO_DATA_CONFIRMED` (quality=0.5)
     - `give_up` → `VERDICT_EXPLORATION_FAILED` (quality=0.0)
     - budget 耗尽 → `VERDICT_BUDGET_EXHAUSTED` (quality=0.0)
   - 全程记录 `step_trace`，可审计

7. **输出**：`db_result`（sql, rows, row_count, source="sql_agent", quality_score, exploration_verdict, exploration_stats, step_trace, finish_summary, formatted_result）

## DB 工具的两个关键问题


### 一、模式判断（exploration_mode）的作用

#### 1.1 两种模式

[runner.py#L57-L59](file:///Users/renwk/workspace/data-knowledge-api/agent/langgraph/tools/sql_agent/runner.py#L57-L59)

```python
MODE_SQL_AGENT = "sql_agent"  # 默认：LLM 驱动的 ReAct 探索
MODE_LEGACY = "legacy"        # 应急回滚：启发式规则流水线
```

#### 1.2 各自做什么

**sql_agent 模式**（默认）：
```
用户问题 → LLM 思考 → 选工具 → 执行 → 观察结果 → 再思考 → ...
```
- 模板短路 → SQL Agent ReAct 子图 → 终态
- 能处理任意复杂查询，但依赖 LLM 可用

**legacy 模式**：
```
用户问题 → 正则/规则提取 → 模板匹配 → 直接执行
```
- 启发式规则流水线（[database_tool.py](file:///Users/renwk/workspace/data-knowledge-api/agent/langgraph/tools/database_tool.py)）
- 零 LLM 开销，但只能处理预定义模式

#### 1.3 模式判断的三大作用

**作用 1：应急回滚开关**

[runner.py#L131-L133](file:///Users/renwk/workspace/data-knowledge-api/agent/langgraph/tools/sql_agent/runner.py#L131-L133)

```python
if exploration_mode == MODE_LEGACY:
    logger.info("[SqlAgentRunner] exploration_mode=legacy，回滚到启发式规则流水线")
    return await get_database_tool().invoke(input_data)
```

当 LLM 服务故障、SQL Agent 子图频繁出错、或需要快速验证时，**一行配置即可整体回滚**到无 LLM 的规则流水线，保证数据库查询能力不中断。

**作用 2：成本控制**

legacy 模式零 LLM 调用，适合：
- 高频固定模式查询（如每分钟上百次的运营看板查询）
- 对延迟极度敏感的场景
- 成本敏感的批量任务

**作用 3：灰度发布的切换器**

```yaml
# conf/sql_agent.yaml
exploration_mode: sql_agent  # 全量 sql_agent
# exploration_mode: legacy   # 全量 legacy
```

上线时可以按租户/场景切换模式，实现灰度发布。

#### 1.4 配置优先级

[runner.py#L120-L123](file:///Users/renwk/workspace/data-knowledge-api/agent/langgraph/tools/sql_agent/runner.py#L120-L123)

```python
exploration_mode = input_data.get(
    "exploration_mode",                                      # 1. 请求级覆盖（最高）
    self._file_config.get("exploration_mode", MODE_SQL_AGENT) # 2. 文件配置
)                                                            # 3. 代码默认值（最低）
```

| 优先级 | 来源 | 适用场景 |
|--------|------|---------|
| 1（最高） | 请求参数 `input_data["exploration_mode"]` | 按租户/场景动态切换 |
| 2 | `conf/sql_agent.yaml` | 全局默认配置 |
| 3（最低） | 代码常量 `MODE_SQL_AGENT` | 兜底默认 |

**Java 类比**：类似 Spring Profile + `@ConditionalOnProperty`，通过配置开关切换 Bean 实现。

#### 1.5 自动降级链（重要）

模式判断不只是"二选一"，还有**自动降级**：

```
sql_agent 模式（默认）
    │
    ├─ LLM 配置不可用 → 自动降级到 legacy
    │  [runner.py#L166-L171]
    │
    └─ SQL Agent 子图执行异常 → 自动降级到 legacy
       [runner.py#L193-L195]
```

也就是说，即使配置成 `sql_agent`，当 LLM 不可用或子图异常时，**自动回退到 legacy 流水线**，不会让查询失败。

### 二、MCP 会话初始化的时机

#### 2.1 MCP 是什么

MCP（Model Context Protocol）是本项目用于**数据库连接管理**的抽象层。[db_runtime.py](file:///Users/renwk/workspace/data-knowledge-api/agent/langgraph/tools/db_runtime.py) 封装了数据库连接池、SQL 执行、schema 发现等能力。

**MCP 会话**：一次数据库连接会话，包含连接池、可用数据库列表、表结构缓存等。

#### 2.2 初始化时机

[runner.py#L135-L144](file:///Users/renwk/workspace/data-knowledge-api/agent/langgraph/tools/sql_agent/runner.py#L135-L144)

```python
# 1. 加载配置并初始化 MCP 会话（共享 DbRuntime）
self._runtime.load_db_config(db_schema_config)  # 加载库 schema 配置
try:
    self._runtime.init_session(tenant_id, mcp_server_name)  # 初始化会话
except Exception as e:
    logger.error(f"[SqlAgentRunner] MCP 会话初始化失败: {e}")
    return self._error_result(start_time, f"MCP 会话初始化失败: {e}")

if not self._runtime.db_tools:
    return self._error_result(start_time, "未从 MCP Server 获取到任何数据库工具")
```

**初始化时机**：**每次 `SqlAgentRunner.invoke()` 调用时**，在模式判断之后、模板短路之前。

#### 2.3 完整时序

```
SqlAgentRunner.invoke(input)
    │
    ├─[1] 模式判断（legacy 直接返回，不初始化 MCP）
    │
    ├─[2] MCP 会话初始化 ← 这里！
    │     ├─ load_db_config() 加载 conf/db_schema.yaml
    │     └─ init_session() 建立连接
    │
    ├─[3] 库白名单校验
    ├─[4] 模板短路
    ├─[5] LLM callable 构建
    └─[6] SQL Agent 子图探索
```

**关键点**：
- **legacy 模式跳过 MCP 初始化**（直接走 `get_database_tool().invoke()`，有自己独立的连接逻辑）
- **MCP 初始化在模板短路之前**，因为模板短路也需要执行 SQL，需要数据库连接

#### 2.4 init_session 做了什么

`DbRuntime.init_session(tenant_id, mcp_server_name)` 的作用：

1. **建立数据库连接池**：根据 `tenant_id` 获取该租户的数据库配置（host/port/user/password）
2. **加载 MCP Server 工具**：从 MCP Server 获取可用的数据库工具集（`list_databases`、`describe_table`、`execute_sql` 等），存入 `self._runtime.db_tools`
3. **缓存 schema 信息**：可选的表结构预加载，加速后续 `describe_table` 调用

#### 2.5 共享 DbRuntime 设计

[runner.py#L80](file:///Users/renwk/workspace/data-knowledge-api/agent/langgraph/tools/sql_agent/runner.py#L80)

```python
def __init__(self, runtime: Optional[DbRuntime] = None, ...):
    self._runtime = runtime or get_db_runtime()  # 进程级单例
```

- `DbRuntime` 是**进程级单例**，多个 `SqlAgentRunner` 实例共享
- 每次调用 `init_session()` 是**会话级初始化**（按 tenant_id 区分），不是重新创建连接池
- 类似 Java 的 `DataSource` + `Connection`：DataSource 是单例，Connection 是按需获取

#### 2.6 何时销毁

MCP 会话**不在 invoke 结束时销毁**，而是由 `DbRuntime` 单例管理生命周期，随进程退出而清理。这样设计的好处：
- 避免频繁建连/断连的开销
- 连接池可复用，提升性能
- 多请求共享 schema 缓存
