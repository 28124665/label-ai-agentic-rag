# 父子分块策略优化设计方案

## 1. 现状分析

### 1.1 当前父子分块数据流

```
文档解析（naive.py）
  └─ parser_config.children_delimiter 解析子块分隔符
     └─ tokenize_chunks 设置 mom_with_weight = 父块内容
        └─ split_with_pattern 按分隔符切分子块

存储阶段（task_executor.py）
  └─ 遍历 chunks，发现 mom_with_weight
     └─ xxhash 生成 mom_id
        └─ 子块写入 mom_id 指向父块（available_int=1，可检索）
        └─ 父块单独写入（available_int=0，不可检索）

检索阶段（search.py）
  └─ settings.retriever.retrieval 检索子块，返回 mom_id 字段
     └─ retrieval_by_children() 无条件将子块替换为父块完整内容
        └─ 本方法在 API 层调用（chunk_app.py / dialog_service.py 等）
        └─ RAGTool 路径不调用此方法
```

### 1.2 RAGTool 路径的当前行为

RAGTool 通过 `LocalRetrieverGateway.retrieve()` 调用 `settings.retriever.retrieval`，**不调用** `retrieval_by_children`。因此 RAGTool 收到的 chunks 是原始子块，带有 `mom_id` 字段但内容为子块文本。

### 1.3 当前 `retrieval_by_children` 的问题

```python
# search.py L712-758 — 当前逻辑
def retrieval_by_children(self, chunks, tenant_ids):
    # 所有有 mom_id 的子块 → 无条件替换为完整父块 content_with_weight
    for id, cks in mom_chunks.items():
        chunk = self.dataStore.get(id, idx_nms[0], [ck["kb_id"] for ck in cks])
        d = {
            "content_with_weight": chunk["content_with_weight"],  # 完整父块
            ...
        }
```

**问题**：
1. 无条件返回全部父块 —— 无论父块多大都全量返回
2. 无 Token 感知 —— 大父块（>2048 tokens）会塞入大量噪声
3. 无窗口截取 —— 不能只返回子块周边的上下文

## 2. 需求定义

### 2.1 核心原则

| 原则 | 说明 |
|------|------|
| 检索永远用小的子块 | 保证向量检索质量（子块匹配精度高） |
| 不无条件返回全部父块 | 根据父块大小采用不同策略 |
| 父块 ≤ 1024 token | 使用完整父块，收益 > 噪声 |
| 父块 1024-2048 token | 不直接全量父块，改用窗口截取子块周边片段 |
| 父块 > 2048 token | 严禁直接把完整父块丢给模型，噪声代价盖过语义收益 |

### 2.2 策略矩阵

| 父块 Token 数 | 策略 | 行为 |
|---------------|------|------|
| 无父块（无 `mom_id`） | `sub_chunk_only` | 保持子块内容不变 |
| ≤ 1024 | `full_parent` | 返回完整父块 `content_with_weight` |
| 1024 ~ 2048 | `window_context` | 子块内容 + 前后各 512 token 的局部上下文窗口 |
| > 2048 | `sub_chunk_only` | 仅返回子块内容，不扩展 |

---

## 3. 设计方案

### 3.1 插入点

在 `_rerank_evaluate_format` 中，**动态截断之后、质量评估之前**插入父块扩展：

```
Rerank 精排 → 动态截断 → ★ 父块扩展（新增） → 质量评估 → 格式化
```

**为什么放在动态截断之后？**
- 动态截断已经去除了低质量子块，只需对保留的子块做扩展
- 减少不必要的父块查询（dataStore.get 是 I/O 操作）
- 质量评估基于扩展后的内容，评估更准确

**为什么放在质量评估之前？**
- 扩展后的内容更完整，Grader 语义评估能基于更充分的上下文
- 基础评估（Rerank 分数）不受影响，仍使用子块原始分数

### 3.3 核心方法：`_expand_parents`

```python
async def _expand_parents(
    self,
    chunks: list[dict],
    tenant_ids: list[str],
    *,
    full_parent_max_tokens: int = 1024,
    window_context_max_tokens: int = 2048,
    context_window_tokens: int = 512,
) -> tuple[list[dict], dict]:
    """父块扩展：根据父块大小采用不同策略。

    对每个截断后的子块，检查其 mom_id 并获取父块，
    按 token 数决定使用完整父块、窗口截取、还是保持子块。

    Args:
        chunks: 动态截断后的子块列表（含 mom_id 字段）
        tenant_ids: 租户 ID 列表
        full_parent_max_tokens: ≤ 此值使用完整父块（默认 1024）
        window_context_max_tokens: ≤ 此值使用窗口截取（默认 2048）
        context_window_tokens: 窗口截取时前后各保留的 token 数（默认 512）

    Returns:
        tuple: (expanded_chunks, expansion_metadata)
            - expansion_metadata: {total, full_parent, window_context, sub_chunk_only}
    """
```

### 3.7 去重逻辑

当多个子块属于同一个父块时：

1. **父块 ≤ 1024 token**：所有子块合并为一条结果，使用完整父块，去重
2. **父块 1024-2048 token**：合并窗口，取所有子块的最小起始位置和最大结束位置，扩展窗口覆盖所有子块
3. **父块 > 2048 token**：每个子块保持独立（不合并），各自保留子块内容

```python
# 伪代码
parent_groups = defaultdict(list)  # mom_id → [sub_chunk_indices]
for i, chunk in enumerate(chunks):
    mom_id = chunk.get("mom_id")
    if mom_id:
        parent_groups[mom_id].append(i)

for mom_id, indices in parent_groups.items():
    parent_chunk = self._fetch_parent_chunk(mom_id, ...)
    parent_tokens = self._count_tokens(parent_chunk["content_with_weight"])

    if parent_tokens <= full_parent_max_tokens:
        # 策略 1：完整父块，去重合并
        merged = build_merged_chunk(indices, parent_chunk)
        replace_group(indices, merged)
    elif parent_tokens <= window_context_max_tokens:
        # 策略 2：扩展窗口覆盖所有子块
        for idx in indices:
            expand_window(chunks[idx], parent_chunk, context_window_tokens)
    else:
        # 策略 3：保持子块，添加父块元信息
        for idx in indices:
            chunks[idx]["_parent_too_large"] = True
```

## 5. 实现细节

### 5.1 `_count_tokens` 实现

```python
@staticmethod
def _count_tokens(text: str) -> int:
    """估算文本 Token 数。

    优先级：
    1. tiktoken（精确）→ 使用 cl100k_base 编码
    2. 字符估算（粗略）→ 中文 ~4 chars/token，英文 ~1 word/token
    """
    try:
        import tiktoken
        enc = tiktoken.get_encoding("cl100k_base")
        return len(enc.encode(text))
    except (ImportError, Exception):
        # 回退：字符级估算
        # 中文字符约占 1.5-2 tokens/char，英文字符约占 0.25 tokens/char
        chinese_chars = sum(1 for c in text if '\u4e00' <= c <= '\u9fff')
        other_chars = len(text) - chinese_chars
        return int(chinese_chars / 1.5 + other_chars / 4)
```

### 5.3 `_extract_window_context` 实现

```python
@staticmethod
def _extract_window_context(
    parent_content: str,
    sub_chunk_content: str,
    context_window_tokens: int = 512,
) -> str:
    """从父块中提取子块周边的局部上下文窗口。

    算法：
    1. 在 parent_content 中定位 sub_chunk_content 的位置
    2. 以子块为中心，向前后各扩展 context_window_tokens 个 token
    3. 如果定位失败，回退到子块内容 + 父块首尾各 context_window_tokens

    边界处理：
    - 子块在父块开头：窗口从父块起始开始，向后取 sub_chunk_tokens + context_window_tokens
    - 子块在父块结尾：窗口向前取 context_window_tokens + sub_chunk_tokens，到父块结束
    """
    # 定位子块在父块中的位置
    pos = parent_content.find(sub_chunk_content.strip())
    if pos == -1:
        # 定位失败，回退：子块 + 父块首尾各一半窗口
        half_win = RAGTool._estimate_char_count(parent_content, context_window_tokens)
        prefix = parent_content[:half_win]
        suffix = parent_content[-half_win:] if len(parent_content) > half_win else ""
        return prefix + "\n...\n" + sub_chunk_content + "\n...\n" + suffix

    # 计算窗口边界
    win_chars = RAGTool._estimate_char_count(parent_content, context_window_tokens)
    start = max(0, pos - win_chars)
    end = min(len(parent_content), pos + len(sub_chunk_content) + win_chars)

    result = parent_content[start:end]
    # 添加截断标记
    if start > 0:
        result = "...\n" + result
    if end < len(parent_content):
        result = result + "\n..."
    return result

@staticmethod
def _estimate_char_count(text: str, tokens: int) -> int:
    """估算 tokens 对应的字符数。"""
    chinese_ratio = sum(1 for c in text if '\u4e00' <= c <= '\u9fff') / max(len(text), 1)
    if chinese_ratio > 0.5:
        return int(tokens * 1.5)  # 中文为主
    else:
        return int(tokens * 4)    # 英文为主
```

### 5.4 `_expand_parents` 核心实现

```python
async def _expand_parents(
    self,
    chunks: list[dict],
    tenant_ids: list[str],
    *,
    full_parent_max_tokens: int = 1024,
    window_context_max_tokens: int = 2048,
    context_window_tokens: int = 512,
) -> tuple[list[dict], dict]:
    """父块扩展主方法。"""
    if not chunks:
        return chunks, {"total": 0, "full_parent": 0, "window_context": 0, "sub_chunk_only": 0}

    stats = {"total": len(chunks), "full_parent": 0, "window_context": 0, "sub_chunk_only": 0}

    # 1. 按 mom_id 分组
    parent_groups: dict[str, list[int]] = defaultdict(list)
    no_parent_indices: list[int] = []
    for i, chunk in enumerate(chunks):
        mom_id = chunk.get("mom_id")
        if isinstance(mom_id, str) and mom_id.strip():
            parent_groups[mom_id].append(i)
        else:
            no_parent_indices.append(i)

    # 无父块的子块保持原样
    stats["sub_chunk_only"] += len(no_parent_indices)

    # 2. 按父块逐个处理
    expanded_chunks = []
    processed_indices = set(no_parent_indices)

    for mom_id, indices in parent_groups.items():
        processed_indices.update(indices)
        sub_chunks = [chunks[i] for i in indices]
        kb_ids = list(set(ck.get("kb_id", "") for ck in sub_chunks if ck.get("kb_id")))

        # 获取父块
        parent = self._fetch_parent_chunk(mom_id, tenant_ids[0] if tenant_ids else "", kb_ids)
        if not parent or not parent.get("content_with_weight"):
            # 父块获取失败，保持子块
            expanded_chunks.extend(sub_chunks)
            stats["sub_chunk_only"] += len(indices)
            continue

        parent_content = parent["content_with_weight"]
        parent_tokens = self._count_tokens(parent_content)

        if parent_tokens <= full_parent_max_tokens:
            # 策略 1：完整父块，去重合并为一条
            merged = self._build_merged_parent_chunk(sub_chunks, parent, mom_id)
            expanded_chunks.append(merged)
            stats["full_parent"] += 1
            logger.debug(f"[RAGTool] 父块扩展 full_parent: mom_id={mom_id}, tokens={parent_tokens}")

        elif parent_tokens <= window_context_max_tokens:
            # 策略 2：每个子块提取窗口上下文
            for ck in sub_chunks:
                sub_content = ck.get("content_with_weight", ck.get("content", ""))
                window_content = self._extract_window_context(
                    parent_content, sub_content, context_window_tokens
                )
                ck["content_with_weight"] = window_content
                ck["_parent_expansion"] = "window_context"
                ck["_parent_mom_id"] = mom_id
                expanded_chunks.append(ck)
            stats["window_context"] += len(indices)
            logger.debug(f"[RAGTool] 父块扩展 window_context: mom_id={mom_id}, tokens={parent_tokens}, sub_chunks={len(indices)}")

        else:
            # 策略 3：父块太大，保持子块
            for ck in sub_chunks:
                ck["_parent_expansion"] = "sub_chunk_only"
                ck["_parent_too_large"] = True
                ck["_parent_mom_id"] = mom_id
                expanded_chunks.append(ck)
            stats["sub_chunk_only"] += len(indices)
            logger.debug(f"[RAGTool] 父块扩展 sub_chunk_only (too large): mom_id={mom_id}, tokens={parent_tokens}")

    # 3. 恢复排序（按原始相似度降序）
    # 完整父块去重后分数取子块均值
    expanded_chunks.sort(key=lambda x: x.get("rerank_score", x.get("similarity", 0)), reverse=True)

    logger.info(f"[RAGTool] 父块扩展完成: total={stats['total']}, full_parent={stats['full_parent']}, "
                f"window_context={stats['window_context']}, sub_chunk_only={stats['sub_chunk_only']}")

    return expanded_chunks, stats

def _build_merged_parent_chunk(
    self,
    sub_chunks: list[dict],
    parent: dict,
    mom_id: str,
) -> dict:
    """合并多个子块为一条完整父块结果。"""
    # 以第一个子块为基础
    merged = copy.deepcopy(sub_chunks[0])
    merged["content_with_weight"] = parent["content_with_weight"]
    merged["chunk_id"] = mom_id
    merged["_parent_expansion"] = "full_parent"
    merged["_parent_mom_id"] = mom_id
    merged["_merged_sub_chunk_count"] = len(sub_chunks)

    # 相似度取所有子块的平均值
    scores = [ck.get("rerank_score", ck.get("similarity", 0)) for ck in sub_chunks]
    merged["rerank_score"] = sum(scores) / len(scores)
    merged["similarity"] = merged["rerank_score"]

    # 合并关键词
    all_kwds = []
    for ck in sub_chunks:
        all_kwds.extend(ck.get("important_kwd", []))
    merged["important_kwd"] = all_kwds

    return merged
```

### 5.5 `_rerank_evaluate_format` 修改

在动态截断之后、质量评估之前插入：

```python
    # 动态截断（§4.6）
    truncated_chunks, truncation_metadata = self._dynamic_truncation(chunks, truncation_config)

    # ★ 父块扩展（新增）：在截断后，只对保留的子块做父块扩展
    parent_child_config = get_config("parent_child", {})
    if parent_child_config.get("enabled", True) and truncated_chunks:
        from common import settings
        tenant_ids = [settings.docStoreConn]  # 实际从 truncated_chunks 的 kb_id 推导
        # 从 chunks 中提取 tenant_id（通过 kb_id 映射）
        kb_ids = list(set(c.get("kb_id", "") for c in truncated_chunks if c.get("kb_id")))
        # 从知识库推导 tenant_id
        tenant_ids = self._get_tenant_ids_from_kb_ids(kb_ids)

        truncated_chunks, parent_expansion_meta = await self._expand_parents(
            truncated_chunks,
            tenant_ids=tenant_ids,
            full_parent_max_tokens=parent_child_config.get("full_parent_max_tokens", 1024),
            window_context_max_tokens=parent_child_config.get("window_context_max_tokens", 2048),
            context_window_tokens=parent_child_config.get("context_window_tokens", 512),
        )
    else:
        parent_expansion_meta = {"total": len(truncated_chunks), "full_parent": 0,
                                  "window_context": 0, "sub_chunk_only": len(truncated_chunks)}

    # 质量评估（在扩展后的文档上评估）
    quality_score, has_relevant, relevant_count, top_score, score_source = \
        await self._evaluate_quality(truncated_chunks, ...)

    # ... 后续格式化逻辑 ...
```

### 5.6 `_get_tenant_ids_from_kb_ids` 辅助方法

```python
def _get_tenant_ids_from_kb_ids(self, kb_ids: list[str]) -> list[str]:
    """从知识库 ID 推导租户 ID。"""
    try:
        from api.db.services.knowledgebase_service import KnowledgebaseService
        kbs = KnowledgebaseService.get_by_ids(kb_ids)
        return list(set(kb.tenant_id for kb in kbs if kb and kb.tenant_id))
    except Exception:
        return []
```

## 6. 边界情况与降级

| 场景 | 处理方式 |
|------|---------|
| 子块无 `mom_id` | 保持子块，标记 `_parent_expansion="sub_chunk_only"` |
| `dataStore.get()` 失败 | 保持子块，记录 WARNING 日志 |
| 父块 `content_with_weight` 为空 | 保持子块 |
| 子块在父块中定位失败 | 使用回退策略：子块 + 父块首尾各 512 tokens |
| 多个子块属同一父块，父块 ≤ 1024 | 合并为一条，使用完整父块 |
| 多个子块属同一父块，父块 1024-2048 | 每个子块独立提取窗口，窗口可能重叠 |
| 多个子块属同一父块，父块 > 2048 | 每个子块独立保持 |
| `parent_child.enabled = false` | 完全跳过父块扩展，行为与改造前一致 |
| tiktoken 不可用 | 回退到字符估算 |

## 8. 风险与回滚

| 风险 | 缓解措施 |
|------|---------|
| dataStore 查询增加延迟 | 仅在动态截断后查询（数量少，通常 3-20 条），且可配置开关关闭 |
| 窗口截取可能切断语义 | 窗口边界以完整句子/段落对齐，避免截断单词 |
| Token 估算不精确 | 优先使用 tiktoken，回退策略已留有余量 |
| 与 API 路径行为不一致 | API 路径 (retrieval_by_children) 保持现有行为不变，仅 RAGTool 路径变更 |

**回滚方案**：设置 `parent_child.enabled = false` 即可完全恢复改造前行为。
