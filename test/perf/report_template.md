# RAG 性能基线测试报告

## 1. 测试目标

本次测试依据二期需求 P2-NFR-01 执行性能基线验证，目标如下：

| 指标 | 目标值 | 测量方式 |
|------|--------|---------|
| 简单查询 P95 | < 2,000 ms | 端到端延迟统计 |
| 单次检索 P95 | < 5,000 ms | 端到端延迟统计 |
| 复杂查询 P95 | < 10,000 ms | 端到端延迟统计 |
| 错误率 | < 1% | HTTP 非 200 / 业务错误占比 |
| 超时率 | < 1% | 超过 60s 未响应占比 |
| 降级触发率 | < 5% | 响应中 `degraded=true` 占比 |
| 并发吞吐量 | ≥ 50 QPS | 稳定负载阶段实测 |

## 4. 测试方法

1. **预热阶段**：5 QPS 持续 2 分钟，预热缓存与模型。
2. **稳定负载阶段**：分别按 10 / 30 / 50 QPS 持续 10 分钟，记录稳态性能。
3. **突发负载阶段**：10 QPS 线性提升至 100 QPS，持续 5 分钟。
4. **恢复阶段**：10 QPS 持续 5 分钟，观察系统恢复能力。
5. **采样指标**：每请求记录延迟、状态码、错误、超时、降级标记、LLM Token 消耗。

## 9. 优化后复测

在完成第 7 章优化建议后，使用 `test/perf/pass_test.py` 执行达标验证。该脚本复用基线压测逻辑，并自动判定二期性能目标是否全部满足。

### 9.1 执行命令

```bash
# 连接真实服务
uv run test/perf/pass_test.py \
  --host http://127.0.0.1:9380 \
  --kb_id <KB_ID> \
  --dataset test/perf/datasets/queries.json

# 无真实服务时生成模拟示例报告
uv run test/perf/pass_test.py --dry-run --optimized --dataset test/perf/datasets/queries.json
```

### 9.2 达标判定标准

| 指标 | 目标值 | 判定来源 |
|------|--------|----------|
| 简单查询 P95 | < 2,000 ms | `by_complexity.simple.p95` |
| 单次检索 P95 | < 5,000 ms | `by_complexity.medium.p95` |
| 复杂查询 P95 | < 10,000 ms | `by_complexity.complex.p95` |
| 错误率 | < 1% | `overall.error_rate` |
| 超时率 | < 1% | `overall.timeout_rate` |
