# RAG 性能基线测试报告

> **说明：本报告为基于模拟数据的示例报告，用于验证测试模板和脚本输出格式。**
> 真实环境测试请使用 `uv run test/perf/baseline_test.py` 连接实际服务后生成。

## 1. 测试目标

本次测试依据二期需求 P2-NFR-01 执行性能基线验证，目标如下：

| 指标 | 目标值 | 测量方式 |
|------|--------|---------|
| 简单查询 P95 | < 2,000 ms | 端到端延迟统计 |
| 单次检索 P95 | < 5,000 ms | 端到端延迟统计 |
| 复杂查询 P95 | < 10,000 ms | 端到端延迟统计 |
| 错误率 | < 1% | HTTP 非 200 / 业务错误占比 |
| 超时率 | < 1% | 超过 60s 未响应占比 |
| 降级触发率 | < 5% | 响应中 `degraded=true` 占比 |
| 并发吞吐量 | ≥ 50 QPS | 稳定负载阶段实测 |

## 4. 测试方法

1. **预热阶段**：5 QPS 持续 2 分钟，预热缓存与模型。
2. **稳定负载阶段**：分别按 10 / 30 / 50 QPS 持续 10 分钟，记录稳态性能。
3. **突发负载阶段**：10 QPS 线性提升至 100 QPS，持续 5 分钟。
4. **恢复阶段**：10 QPS 持续 5 分钟，观察系统恢复能力。
5. **采样指标**：每请求记录延迟、状态码、错误、超时、降级标记、LLM Token 消耗。

> 本示例报告数据由 `baseline_test.py` 的 `--dry-run` 模式根据查询复杂度分布模拟生成。

## 6. 瓶颈分析

| 序号 | 瓶颈点 | 证据 | 影响 |
|------|--------|------|------|
| 1 | Rerank 延迟随 QPS 上升 | stable-50 阶段 P95 较 stable-10 上升 68% | 拉高复杂查询端到端延迟 |
| 2 | 突发流量下超时率上升 | burst 阶段超时率达到 1.00% | 接近 SLA 上限 |
| 3 | LLM 首 token 时间在复杂查询中偏高 | complex 查询 P95 接近 10s | 影响用户体验 |

## 7. 优化建议

| 优先级 | 优化项 | 预期收益 | 负责人 |

## 8. 结论

本次示例测试显示，在模拟负载下系统整体错误率、超时率、降级率均满足二期基线目标；简单查询与单次检索 P95 达标，复杂查询 P95 接近 10s 阈值。建议在真实环境部署后执行完整基线测试，并根据 Rerank 与 LLM 链路数据进行针对性优化，再进入 Task 11 性能达标测试。
